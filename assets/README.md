# assets

`demo.gif` is a recording of a real session, not a mock-up: the plugin action fires, the chip
turns `●`, whisper transcribes, and the transcript is typed into a Claude Code pane and
submitted. Rebuild it with one command:

```sh
./assets/make-demo.sh
DEMO_LINE="Rename the parser module." ./assets/make-demo.sh
```

| file            | what it is                                                       |
| --------------- | ---------------------------------------------------------------- |
| `make-demo.sh`  | the entry point: sets up, records, renders, cleans up             |
| `say.py`        | speaks the instruction and captures it as the demo's microphone   |
| `record.py`     | runs Herdr in a pty and drives the dictation, capturing frames    |
| `render.py`     | turns captured frames into the GIF                                |
| `prompt.wav`    | the spoken instruction, regenerated by `say.py`                   |

Needs `uv`, `herdr`, `claude`, `ffmpeg`, `fontconfig`, `git`, and PulseAudio or PipeWire with
`spd-say`. `make-demo.sh` names anything absent and stops. Python dependencies (`pyte`,
`Pillow`) install into a throwaway virtualenv, never system-wide.

Nothing durable is changed. The Herdr session, the sample repo and the virtual audio device are
created for the recording and removed after; the default microphone is never repointed, because
only the plugin's own recording stream is moved onto the virtual device.

`DEMO_LINE`, `DEMO_REPO`, `DEMO_SESSION`, `DEMO_COLS`, `DEMO_ROWS`, `DEMO_ANSWER_SECS` and
`DEMO_GIF` override the defaults.
